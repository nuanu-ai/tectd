# Apply workspace and finish safety within native authority

First establish the exact repository, branch/ref, worktree identity and ownership. Distinguish a linked worktree from a submodule and a host-managed detached checkout. An already valid isolated workspace does not require another worktree. Prefer an applicable available native mechanism; use the authorized Git fallback when necessary. A tool existing in a generic skill example does not make it available here.

Recorded user preferences and authorization satisfy the corresponding consent question. A permission failure does not authorize working in a protected or foreign checkout. A `.worktrees` or `worktrees` path is not proof that this task owns its contents. Establish actual creation/ownership and preserve unrelated dirty files.

In a reference-only phase, return workspace/branch provenance, intended commands and required authority in the phase output. Do not create a worktree, install dependencies, edit or commit `.gitignore`, check out another branch, merge, push or clean up. During execution, perform only the setup actually required by the authorized task. Generic package-manager detection does not authorize an unnecessary install.

At finish, use the accepted destination/base and integration authority. Do not repeat a fixed menu when the user already made the decision. A skill's menu is not a grant to merge, deploy or delete. Review/read-only approval and successful source tests do not themselves authorize those effects.

Preserve the checkout after a PR/handoff unless cleanup of that exact task-owned workspace is authorized. A removal refusal requires inspecting the reason and preserving the files; it never implies `--force`. Do not clean up another workspace because it appears old. Check the evidence for the actual integration result when integration is part of the task; a previous tree's green run is not proof of a changed tree.

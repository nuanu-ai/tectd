# Apply systematic debugging to a diagnosis-only Slice

Preserve the four-part method: evidence and reproduction, comparison with a working pattern, one explicit hypothesis at a time, and a verified future fix strategy. Read complete relevant source/history and actual errors before naming a cause. Do not stack guesses or substitute a successful symptom workaround for a causal explanation.

The upstream implementation phase is a future-work reference here. The current Debug pipeline does not authorize a cause-level fix, test-source creation, production logging changes, dependency installation or a new harness. Use its phase-specific permitted observations and probes; describe the future RED/GREEN obligation where required.

Use existing diagnostic evidence first. Additional instrumentation requires a concrete missing observation and authority for that environment. Do not execute example environment dumps, print credentials or record secret values. A shell command in a reference is not an approved command for the current system.

Preserve condition-based waiting, defense-in-depth and root-cause-tracing resources. A reference to an unbundled helper does not make that helper available; do not search an installed plugin cache for a substitute. Repeated failed hypotheses require reassessing the causal model with the new evidence. Ask for an owner decision only when the necessary choice exceeds the task's authority; otherwise continue the bounded investigation and report what remains unproven.

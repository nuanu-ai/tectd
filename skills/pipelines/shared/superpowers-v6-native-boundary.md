# Native boundary for selected Superpowers v6 methods

Read this adapter with the exact pinned upstream bodies assigned to the current phase. Upstream provides the substantive method; the current native phase contract and recorded user authority determine its allowed application. Existing explicit authorization remains valid. A generic approval question, menu, suggested directory or named agent in a body does not replace that authorization or create a new gate.

The backend owns the run, current phase, immutable inputs/outputs, exact reads, review bindings, retry/revisit and completion. Use those carriers. Do not create a second progress lifecycle, dispatch topology, hidden task ledger or branch lifecycle from an upstream instruction. A skill read is not proof that its substantive work was done.

Respect the assigned phase outcome. Debug produces diagnosis and a future fix contract; Operational Preparation produces preparation; Research assignment phases produce packets; Procedure inventory produces a read-only handoff. Their development-method references do not authorize implementation, test source, worktree creation, dispatch or branch changes. Operational Execution performs only its currently authorized action/checkpoint. Full execution follows its selected native delivery mode and preserved review requirements.

Current model/delegation policy remains authoritative. An upstream request for a subagent does not override a requirement that the primary agent personally perform intellectual work. When a required independent review cannot be supplied under the active policy, record that exact gap; two passes by the same author are not two independent reviewers.

Keep exact source/artifact paths from the native contract. Inspect recorded evidence before repeating work. Required checks still run, but repeated full suites, unrelated infrastructure and an unsolicited audit harness do not become deliverables because a generic skill mentions testing. Preserve separate source, review, runtime, deployment and user-outcome proof.

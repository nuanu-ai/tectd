# Research source and evidence plan

Use at R03 with the exact brief, question table and context. Read the delivered writing-plans skill and native adapters for bounded, checkable planning. Apply them to evidence work; do not produce a software implementation plan, prescribe subagents or introduce their external execution router.

Map each question to concrete source families and candidate locators or bounded discovery routes. Appropriate families include authoritative documents, standards, owner statements, source code and Git history, issue/CI traces, logs and runtime snapshots, datasets, prior studies, public web sources and authorized transcripts/media. Give each source a role: primary authority, corroboration, history, disconfirmation, freshness check or background. Copies and summaries of one source do not provide independent corroboration.

In `source-map.md` record question IDs, families, locators, source roles, authority expectation, version/time requirements, access and sensitivity, permitted use, likely limitations, contradiction probes and explicit source gaps. A vague instruction to search everywhere is not a source plan.

In `evidence-plan.md` order bounded reads by likely evidential value, authority, risk and cost. For each specify question, method, path/query/URL or discovery constraint, proof needed, acceptance/rejection criteria, citation/excerpt rules, source-declared versus collection date, expected custody record and stop condition. State when snapshot proof suffices and when current verification is necessary. Prefer primary material for consequential claims; document a justified limitation when only secondary material exists.

Include disconfirming searches and negative-result capture: exact inspected scope, terms, time bounds and access failures. Distinguish evidence absent in the inspected scope from material that was inaccessible, unsafe, stale or never checked. Allocate a realistic time/context/search budget and identify which result would stop further collection or change direction. Do not invent a universal query count.

Declare allowed read-only probes and separately identify actions that require different authorized work. A local calculation over existing data can be planned; running found code, installing its dependencies, paid experiments or mutating live systems cannot be smuggled into collection. Record precise authority/access gaps and the next owner.

Set `source_coverage`, `permitted_reads`, `negative_probes` and `collection_budget`. Every question has a source route or an explicit gap. Return to R02 for an unanswerable/ambiguous question; advance when collection can be executed without guessing scope or authority.

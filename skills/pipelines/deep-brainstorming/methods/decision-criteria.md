# Decision criteria and decisive unknowns

Use at B03 to define what makes an option good for this actual decision. Read the current brief and classified premises.

Separate hard constraints from comparative criteria and preferences. A hard constraint needs its source, scope and observable failure condition; do not call every preference mandatory. For each criterion explain whose outcome it serves, direction of improvement, relevant horizon and how alternatives can be compared. Cost, reversibility, time, complexity, risk and strategic fit matter only when they affect this decision.

Identify trade-offs that cannot all be optimized simultaneously. State priorities already supplied by the owner. If an unresolved priority could reverse the choice, name the exact preference question rather than inventing weights. Numerical scores are useful only when grounded in meaningful measurements and assumptions; do not fabricate a precise ranking from adjectives.

List decisive unknowns: the fact, estimate or preference that could change eligibility or the preferred option, the alternatives it affects, the possible answers and how each would change the choice. Distinguish evidence needs from value judgments. Rank further inquiry by its decision value rather than curiosity.

Produce `decision-criteria.md` with constraints, comparative criteria, known priorities, conflict/trade-off pairs, decision thresholds, decisive unknowns and the acceptable uncertainty of the requested outcome. Set `criteria` and `decisive_unknowns` fields.

Return to B01/B02 if criteria require unsupported intent or a misclassified premise. Proceed when options can be compared honestly with the current priorities, or mark exactly which owner question remains. A recommendation can be conditional; a condition that prevents the requested decision must remain visible.

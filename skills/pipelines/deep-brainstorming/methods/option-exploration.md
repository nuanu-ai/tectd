# Explore the option space

Use at B04 after framing, context and criteria. Generate materially different ways to achieve the outcome; avoid cosmetic variants that assume the same untested premise.

Give every serious option a stable ID and explain its mechanism, intended benefit, necessary assumptions, scope, dependencies, principal costs/risks and reversibility. Keep an existing baseline, doing less, staged commitment or rejecting the initiative when it is a meaningful alternative. If the baseline is invalid or irrelevant, record the reason rather than adding a fake option to meet a quota.

Explore the strongest plausible alternative to the initial favorite. Separate complementary parts that could be combined from incompatible strategic choices. A hybrid is justified by a mechanism and trade-off, not by combining all advantages while ignoring interaction cost. Eliminate an option only on a stated constraint or reason; retain rejected options and the basis of rejection.

Use enough alternatives to expose the consequential design space, usually a few strong ones. Do not impose a fixed option count or exhaustively enumerate trivial possibilities. Mark hypotheses as hypotheses; an attractive feature list is not evidence of feasibility. Record which unknowns could make an option invalid or dominant.

Write `options.md` with IDs, mechanism, scope, premise/source links, eligibility, benefits, costs, risks, assumptions, conditional variants and rejected alternatives. Set `options`, `baseline_disposition` and `assumptions`.

Return to B02/B03 if new options reveal a missing constraint or criterion. Otherwise hand the current exact option set to B05. Do not silently choose a winner, execute a prototype or create a new development pipeline merely to make an option convincing.

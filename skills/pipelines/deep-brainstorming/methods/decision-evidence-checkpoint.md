# Decision evidence checkpoint

Use at B05 to test the premises that could change the choice. Read the exact B01–B04 basis, new inputs, delivered DK and any accepted Research result. This is a dependency checkpoint, not approval of the whole decision.

For each decisive assumption state the needed evidence, what is actually known, its source/currentness/scope and the consequence if false. A small bounded read within existing authority belongs here; preserve its locator and limitations. If the main missing work is substantial source collection, qualification and synthesis, issue a separate Research request rather than hiding it inside an endless B05.

For that request, persist `evidence-checkpoint.md` and submit `research_checkpoint` with a precise question, answer criteria, reason for separate Research and its own research inquiry contract. Use `waiting_research`, WaitingInput and Continue. The backend supplies an immutable checkpoint ID/digest and exact producer/phase/output/basis references. The Research candidate must bind this checkpoint, not require the entire Brainstorming Slice to be completed. It still follows normal candidate review/open/begin.

Do not replace the native checkpoint with a path or a fabricated external result. While it is outstanding, preserve the wait. Accept or reject only the exact result from the bound Research using `slice.pipeline.checkpoint.resolve`; cancel with a reason if the request is superseded. An inconclusive response can be useful evidence of uncertainty but cannot be interpreted as proof of a favored hypothesis.

On resume, compare the actual answer with the original criteria and option assumptions. Preserve the old exact basis as history. If evidence changes premises, priorities or feasible options, return to B02, B03 or B04 respectively; existing downstream outputs become stale. Otherwise record how the result changes confidence or conditions and continue to B06. Normal replacement of the current B05 output after acceptance is not permission to rewrite the historical request.

Set `evidence_disposition` to `ready`, `conditional`, `waiting_research` or `waiting_authority`, and record `decisive_assumptions`. Conditional progression requires the uncertainty and its effect to remain explicit; a missing essential owner decision stays a wait. A changed fundamental goal returns to explicit framing revision rather than extending the research question unnoticed.

# Knowledge Change: impact and owned-copy plan

Read the proposed diff, domain receipts and backend-discovered bindings/dependencies/active contexts. Determine which consumers change, what is synchronously invalidated, what needs review and who owns follow-up. Include newly applicable norms: a phase with a previously empty manifest can be affected. Do not limit impact to prior readers.

For a reviewed cross-domain derivation, retain the exact source revision and necessary conditions. A changed source makes the dependent interpretation review-bound; the backend cannot invent the new interpretation. Preserve unaffected projects and completed historical work. Publication does not retroactively undo an external operation.

Supersession must name exact replacement bindings and successor suitability; automatic silent repinning is forbidden. Retraction takes effect without waiting for a replacement or consumer repair. Required withdrawn knowledge becomes an explicit context gap. A new follow-up is a proposal with an owner, not proof that another task was performed.

For erase, review the backend-owned copy inventory: canonical revisions/events that contain content, source fragments, Change baseline/proposal/output/receipt payloads, phase manifests/outputs and native storage terms. State which copies belong to the requested content, which are shared, which are inaccessible and which are backups/outside control. Do not delete a whole shared source merely because one unit references it. Unknown deletion scope is a blocker. Preserve only approved minimal metadata in tombstones.

The inventory follows exact ownership into derived attempts/artifacts, managed Results and their planning descendants. Earlier independent evidence does not become a derivative merely because a later phase in the same run uses the unit. Review both the frozen external copy references and the backend's explicit control-payload scope for this exact Knowledge Change. The latter covers its own bounded review/publication/request records created to finish the already qualified operation set; it does not authorize deletion in another run. Recording the expected review itself must not cause an endless impact-review loop. New external derivatives or a changed material operation/scope require a refreshed assessment.

Define visibility closure, live-copy purge, native dictionary/cache handling and backup/restore disposition separately. Absence from current query is not full purge; pending backup retention is not completion of an unrestricted erase. The backend executes the accepted effects plan and returns receipts. No manual destructive command, broad garbage collection, hidden substring scrub or infrastructure change is authorized by this method.

Return the substantive impact/erasure assessment, exact affected references, required effects, allowed pending obligations and owners. Preserve the original completion requirement; do not weaken it after a failed effect.

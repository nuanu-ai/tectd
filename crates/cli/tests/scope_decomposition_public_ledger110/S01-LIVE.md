# S01 one-shot harness

The current test-only source case uses call ID `tectd-jev-s01-evidence-2026-09-28-2`. It follows Slice 01's authored-alternatives contract: both arrangements preserve every applicable source fragment and cover the same ranking-only, explicit-disposition, source/configuration/policy/preservation recheck, existing-caller and distinct-Verifier work. The cohesive alternative is one Scope; the partitioned alternative has two Scopes with an explicit local dependency from the effect Scope to the preparation Scope. The previous `...-1` request and used marker are retained as historical evidence. This case does not alter ranking rules or production configuration.

`s01_live.rs` is an ignored, test-only fixture. It requires a new PostgreSQL 18.6 cluster and an empty dedicated database named `tect_s01_live_*`. Supply the cluster system ID, database OID and port through `TECT_TEST_EXPECTED_PG_SYSTEM_ID`, `TECT_TEST_EXPECTED_DB_OID`, and `TECT_TEST_EXPECTED_PG_PORT`; set `TECT_TEST_DISPOSABLE_PG=1`, `TECT_TEST_RUNTIME_ROLE=tect_ci`, `TECT_TEST_EXPECTED_DB_NAME`, `TECT_TEST_ADMIN_URL`, and `TECT_TEST_RUNTIME_URL`. The URLs must point to the same loopback database with `postgres` and `tect_ci` respectively. Keep the data directory after a test, including failures.

Run only the ignored `s01_live::real_s01_one_shot` test with `JEV_S01_ONE_SHOT_MODE=preflight` for a zero-send shape check. It migrates the empty database, validates a signed owner policy through the runtime trust key, prepares two source-covering alternatives and writes an exclusive `*.preflight-native-verified.request.json` artifact. It then records a public `no_call` under a deliberate Deny budget adapter and verifies zero dispatches. The `budget_policy_invalid` no-call reason reflects that adapter; the signed policy has already passed a separate typed read. Preflight never reads `TYPESAFE_API_KEY`.

The preflight request contains random fixture IDs. A later `send` invocation creates a **different** fresh fixture and a fresh `*.request.json`; its bytes and SHA-256 must be reviewed in that invocation. The process waits for the exact newline-terminated `SEND JEV <sha256>` line, then exclusively creates and syncs the fixed `*.used` marker before any HTTP send. The marker is never removed or retried by the harness. The provider has a 15-second HTTP timeout, no redirects or retries, a 45,000-byte request cap and 65,536-byte response cap. The signed test budget allows one provider call, 24,000 input tokens, 2,000 output tokens, 45,000 request bytes and 60 seconds elapsed; the schema requires `retry_dispatches=1`, while the fixture has no retry route.

After any send outcome, the harness reads one sealed dispatch, exact request bytes and digest, raw response bytes/hash/reference, send certainty, transport outcome, and budget reservation/consumption. Valid selective advice gets an explicit disposition, selected save and distinct Verifier observation. Nonselective valid advice gets `reject_all` and no selected save. Provider failure is reported after audit without claiming success. Retain the database, request and marker for investigation.

The separate ignored `loopback_selective_native_receipt`, `loopback_nonselective_native_receipt`, `loopback_failure_retains_transport_audit`, and `loopback_rejects_changed_reviewed_body` tests use local HTTP or a pre-send guard only. They need their own empty databases under the same identity rules and do not read the provider key or use the one-shot marker.
